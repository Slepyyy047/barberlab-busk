# BARBERLAB — барбершоп у Буську

Український сайт: головна, послуги, команда, контакти, правові сторінки та захищена адмінпанель. Next.js 16, React, TypeScript. SQLite і фотографії зберігаються на серверному диску; браузерне сховище не використовується як база бізнес-даних.

## Запуск на Windows

Потрібен Node.js 24 LTS та npm. У PowerShell:

```powershell
cd barberlab-busk
npm ci
npm exec tsx scripts/import-portraits.mjs
npm run build
npm run start
```

Сайт: http://127.0.0.1:3000. Для розробки: `npm run dev`.

## Безпечний доступ до адміністрації

```powershell
npm run admin:create
```

Команда попросить ім’я користувача та пароль від 12 символів. Пароль вводиться приховано, двічі. Потім відкрийте http://127.0.0.1:3000/admin. У проєкті немає стандартного адміністратора або публічного пароля. Тестові облікові записи видаляються після перевірки. Повторне створення того самого користувача змінює пароль та відкликає його сесії. Не залишайте облікові дані в змінних середовища або файлах репозиторію.

У кабінеті можна додавати та редагувати послуги, міняти ціну/тривалість/категорію, приховувати й упорядковувати записи; керувати майстрами та їхніми портретами; завантажувати, описувати, приховувати, сортувати і видаляти фото; оновлювати контакти, запис, соцмережі, години та надані відгуки. «Зберегти зміни» одразу оновлює публічний сайт. Видалення фото є окремою дією зі сховищем і потребує попереднього збереження інших змін.

## Дані та резервні копії

За замовчуванням дані лежать у `data/barberlab.sqlite`, а зображення — у `data/uploads`. `data/` виключено з Git та архіву вихідного коду. Облікові записи і сесії також зберігаються в SQLite. Файли проходять перевірку формату, розміру та роздільності, перетворюються на WebP; максимальний початковий розмір — 8 МБ.

Проста узгоджена копія: зупиніть сервер, скопіюйте **всю** папку `data` в окремий захищений каталог, тоді запустіть сервер знову. Для відновлення зупиніть сервер, поверніть папку `data` з копії та запустіть сайт. Не копіюйте лише `.sqlite` під час запису: SQLite використовує WAL. Зберігайте копії поза сервером, шифруйте носій і періодично перевіряйте відновлення. Резервна копія містить парольні хеші та сесії, тому вона приватна.

## Перед виробничим запуском

### Публічна версія на Vercel

Vercel показує зафіксований знімок опублікованого вмісту з `lib/hosted-content.json` і портрети з `public/hosted-media/`. Він зберігає сторінки, контакти, ціни, відгуки та зовнішній запис через Altegio. Адмінпанель, адміністративний API та файлові завантаження на Vercel повертають 404, бо там немає постійного диска для SQLite та фото. Локальний запуск продовжує працювати зі своєю базою і адмінкою.

Після локальних змін через адмінку повторіть `node scripts/export-hosted-content.mjs`, перевірте оновлені файли та зробіть новий деплой. Скрипт бере лише видимі послуги, майстрів і фото, публічні налаштування та відгуки; облікові записи й сесії не експортує. Для живої адмінпанелі потрібен сервер із постійним диском або окреме сховище даних.

Публічний сайт розгорнуто на https://barberlab-busk.vercel.app/. Ця версія працює зі знімком опублікованого вмісту. Для живої адмінпанелі потрібен один Node.js 24 сервер з постійним диском: VPS або контейнер з примонтованим томом. Ефемерна файлова система serverless не підходить для записуваного SQLite-сховища.

1. Встановіть залежності, зберіть сайт; налаштуйте керований процес і HTTPS reverse proxy. Команда `npm run start` слухає лише loopback; proxy має працювати на тому самому сервері. Для контейнера внутрішній сервер запускайте `npx next start --hostname 0.0.0.0`, доступ зовні захистіть proxy.
2. Задайте `BARBERLAB_DATA_DIR` на постійному томі, наприклад `/var/lib/barberlab`. Надайте право запису лише сервісному користувачу, налаштуйте резервні копії бази **і** фото. Не роздавайте цей каталог як статичний.
3. Створіть адміністратора інтерактивною командою. Доступ до файлової системи та резервних копій обмежте власниками. Для додаткового приватного sales-preview використовуйте обмеження доступу на proxy; `noindex` сам по собі не є авторизацією.
4. Налаштуйте `BARBERLAB_APP_ORIGIN=https://підтверджений-домен` як єдиний дозволений origin адміністративних змін, і `BARBERLAB_PUBLIC_URL` для canonical та sitemap. Без `BARBERLAB_APP_ORIGIN` адміністративні зміни доступні лише на loopback для локальної розробки. Проксі має передавати HTTPS; перевірте прапорець Secure у cookie після входу. Запити на зміну даних також потребують CSRF-токен поточної сесії в `X-CSRF-Token`.
5. До дозволу власників залишайте `BARBERLAB_ALLOW_INDEXING` вимкненим. Зараз сторінки, HTTP-заголовки й robots забороняють індексацію. Після дозволу встановіть `BARBERLAB_ALLOW_INDEXING=true`, вкажіть реальний домен, перебудуйте сайт. Адмінпанель та API залишаються закритими для індексації.
6. Підтвердіть актуальність цін, команди, робочих днів, доступності входу/паркування, оплати карткою/NFC, кави, дитячих послуг і місця очікування. Дані — наданий знімок, а не жива перевірка Google.

Обмеження входу зберігається в SQLite: 10 невдалих спроб на ім’я адміністратора та 100 загалом за 15 хвилин. Воно спільне для процесів **на одному сервері з тим самим локальним файлом бази даних**. Значення `X-Forwarded-For` не впливає на ліміти. Для інстансів на різних серверах потрібне спільне серверне сховище даних і лімітів (наприклад, Redis або PostgreSQL); SQLite у режимі WAL не призначена для спільного доступу через мережеву файлову систему.

## Чого бракує від власників

- Оригінальний векторний логотип для точного відтворення знака. Зараз використовується погоджена користувачем генерація підвищеної роздільності; це реконструкція, а не точна векторизація.
- Оригінальні фото салону та робіт. П’ять наданих портретів підключено; вихідні файли включено в assets/team. Галерея й окрема сторінка «Про нас» тимчасово прибрані; дані CMS збережені. Згенеровані інструменти та розмитий фон — декоративні матеріали, створені за запитом користувача.
- Підтверджений тижневий розклад, домен та конфігурація виробничого сервера. Для локального функціонування зовнішні ключі не потрібні.
- Перевірка відкриття Altegio з реального пристрою: всі CTA мають надане посилання; зовнішній веб-інструмент не відкрив сторінку; прямий HTTP-запит отримав 200, але завантажений динамічний інтерфейс і вільні слоти не перевірені. Сайт не створює фіктивних бронювань і не обіцяє попередній вибір послуги.

## Перевірки

GitHub Actions (`.github/workflows/ci.yml`) запускає lint, typecheck, тести, production build і HTTP smoke test на pull request та push у main. CI використовує тимчасовий каталог даних; власницька база й завантаження не входять у репозиторій. Автоматичний деплой не налаштований.

`/api/health` повертає `200 {"status":"ok"}` лише коли наявна SQLite проходить quick check, CMS-вміст валідний і каталог даних доступний для читання/запису. Помилка повертає `503 {"status":"unavailable"}` без серверних шляхів і подробиць. Endpoint не створює базу та не змінює схему; відповіді не кешуються. Перевірка прав каталогу не гарантує наявності вільного дискового простору.

Серверні помилки й успішні дії адміністратора (вхід, вихід, збереження, завантаження/видалення фото) записуються у stderr як JSON із часом, типом події та вибраними полями. Паролі, cookies, CSRF-токени, тіла запитів і сирі повідомлення винятків не записуються. Це журнали процесу, а не постійний журнал у базі: збір, ротацію та сповіщення потрібно налаштувати на майбутньому хості. Sentry, аналітика та зовнішні повідомлення не підключені.

Читання CMS на публічних сторінках повторно використовується лише в межах одного серверного рендеру. Немає глобального кешу, який приховував би збережені адміністратором зміни. Файли `/api/media/` мають незмінні UUID-адреси та річний cache lifetime; сторінки й адміністративні API залишаються динамічними. CDN, PWA й offline cache не підключені.

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm run smoke
npm run test:accessibility
npm run test:browser
node tests/run-isolated-admin.mjs
node tests/filter-regression.mjs
node tests/run-corrective-isolated.mjs
node tests/reference-browser.mjs
```

Старі браузерні тести потребують Microsoft Edge та запущеного сайту на `127.0.0.1:3000`. Вони використовують окремий headless-профіль без особистих cookies. Обгортка адміністративного тесту самостійно запускає окремий сервер на :3101 із тимчасовою базою та прибирає їх після перевірки. Не запускайте admin-browser.mjs напряму проти бази власника. `test:accessibility` після build сам запускає тимчасовий production-сервер на вільному порту: у Windows використовує Edge, а в Linux — Chromium, встановлений через `npx playwright install --with-deps chromium`. Ця перевірка входить у CI та охоплює клавіатуру, контраст, alt, cookie й відкликання дозволу на карту.

Результати та знімки — у `verification/`; докладніше у `VERIFICATION.md`. Production-залежності перевірено npm audit. Dev-інструментарій ESLint має upstream-застереження для braces/micromatch; на серверний runtime ці пакети не входять. Перед публічним запуском повторіть аудит і перевірки на вибраному хості.

## Джерела та ліцензії

- Логотип і бізнес-дані — надані користувачем; права на публічне використання підтверджує власник.
- На головній вступ і команда розташовані перед послугами. Закріплений хедер веде до секцій; повні списки послуг і майстрів залишаються окремими сторінками. Three.js не використовується. Фільтровані послуги доступні одразу, а рух зупиняється за налаштуванням reduced-motion.
- 15 PNG інструментів і розмитий фон створені вбудованим image_gen за дозволом користувача. Портрети майстрів — справжні надані фото. Точні промпти: assets/tool-generation.md, assets/background-generation.md, assets/logo-generation.md.
- Next.js і React — MIT; sharp — Apache-2.0. Ліцензії залежностей у їхніх пакетах.
- Manrope та Oswald — SIL Open Font License 1.1. Шрифти з Google Fonts збережено локально; тексти ліцензій у `public/fonts/`. Сайт не звертається до Google Fonts під час перегляду.
- Google-карта потребує дозволу зовнішнього контенту в налаштуваннях cookie та окремого натискання «Показати карту». Відмова не блокує сайт, дзвінок чи зовнішній запис; доступний звичайний маршрут-посилання. У футері можна змінити або відкликати дозвіл, а вбудована карта при цьому прибирається. Необов’язкові SDK, рекламні пікселі й аналітика не встановлені.
- Вибір cookie зберігається у localStorage як версія 1, boolean externalMedia та час збереження на 180 днів, без ідентифікатора користувача й без надсилання на сервер. Необхідна cookie `barberlab_admin` діє до 12 годин і встановлюється лише після входу адміністратора. Якщо зберігання в браузері заблоковане, вибір діє лише у поточній вкладці.
- `/privacy`, `/terms`, `/cookies` та `/licenses` описують фактичну реалізацію. Власник має доповнити офіційне найменування відповідальної особи та підтвердити права фотографа/згоди на портрети; проєкт не вигадує ліцензій на ці матеріали. Походження активів і чинні ліцензії шрифтів перелічені в `ASSET-LICENSES.md` та на сторінці ліцензій.
- Клавіатура: skip-link переводить фокус до main, мобільне меню переводить його до першого пункту й закривається Escape. Декоративні зображення приховані від assistive technology, портрети мають опис; опубліковані фото галереї вже проходять серверну перевірку непорожнього alt. У футері є кнопка зупинки анімацій; системне reduced-motion також підтримується.
