# BARBERLAB — барбершоп у Буську

Український сайт: головна, послуги, команда, контакти та захищена адмінпанель. Next.js 16, React, TypeScript. SQLite і фотографії зберігаються на серверному диску; браузерне сховище не використовується як база даних.

## Запуск на Windows

Потрібен Node.js 24 LTS та npm. У PowerShell:

```powershell
cd barberlab-busk
npm ci
npm exec tsx scripts/import-portraits.mjs
npm run build
npm run start
```

Сайт: http://127.0.0.1:3000. Для розробки: `npm run dev`.

## Безпечний доступ до адміністрації

```powershell
npm run admin:create
```

Команда попросить ім’я користувача та пароль від 12 символів. Пароль вводиться приховано, двічі. Потім відкрийте http://127.0.0.1:3000/admin. У проєкті немає стандартного адміністратора або публічного пароля. Тестові облікові записи видаляються після перевірки. Повторне створення того самого користувача змінює пароль та відкликає його сесії. Не залишайте облікові дані в змінних середовища або файлах репозиторію.

У кабінеті можна додавати та редагувати послуги, міняти ціну/тривалість/категорію, приховувати й упорядковувати записи; керувати майстрами та їхніми портретами; завантажувати, описувати, приховувати, сортувати і видаляти фото; оновлювати контакти, запис, соцмережі, години та надані відгуки. «Зберегти зміни» одразу оновлює публічний сайт. Видалення фото є окремою дією зі сховищем і потребує попереднього збереження інших змін.

## Дані та резервні копії

За замовчуванням дані лежать у `data/barberlab.sqlite`, а зображення — у `data/uploads`. `data/` виключено з Git та архіву вихідного коду. Облікові записи і сесії також зберігаються в SQLite. Файли проходять перевірку формату, розміру та роздільності, перетворюються на WebP; максимальний початковий розмір — 8 МБ.

Проста узгоджена копія: зупиніть сервер, скопіюйте **всю** папку `data` в окремий захищений каталог, тоді запустіть сервер знову. Для відновлення зупиніть сервер, поверніть папку `data` з копії та запустіть сайт. Не копіюйте лише `.sqlite` під час запису: SQLite використовує WAL. Зберігайте копії поза сервером, шифруйте носій і періодично перевіряйте відновлення. Резервна копія містить парольні хеші та сесії, тому вона приватна.

## Перед виробничим запуском

Це локально перевірена конфігурація. Хостинг, домен і публічний запуск не виконувались. Потрібен один Node.js 24 сервер з постійним диском: VPS або контейнер з примонтованим томом. Звичайний статичний хостинг та ефемерна файлова система serverless не підходять для цього сховища.

1. Встановіть залежності, зберіть сайт; налаштуйте керований процес і HTTPS reverse proxy. Команда `npm run start` слухає лише loopback; proxy має працювати на тому самому сервері. Для контейнера внутрішній сервер запускайте `npx next start --hostname 0.0.0.0`, доступ зовні захистіть proxy.
2. Задайте `BARBERLAB_DATA_DIR` на постійному томі, наприклад `/var/lib/barberlab`. Надайте право запису лише сервісному користувачу, налаштуйте резервні копії бази **і** фото. Не роздавайте цей каталог як статичний.
3. Створіть адміністратора інтерактивною командою. Доступ до файлової системи та резервних копій обмежте власниками. Для додаткового приватного sales-preview використовуйте обмеження доступу на proxy; `noindex` сам по собі не є авторизацією.
4. Налаштуйте `BARBERLAB_APP_ORIGIN=https://підтверджений-домен` для перевірки походження запитів, і `BARBERLAB_PUBLIC_URL` для canonical та sitemap. Проксі повинен перезаписувати клієнтські X-Forwarded-For і коректно передавати HTTPS protocol; перевірте Secure у cookie після входу. Використовуйте лише один процес застосунку для чинного обмеження спроб входу в пам’яті.
5. До дозволу власників залишайте `BARBERLAB_ALLOW_INDEXING` вимкненим. Зараз сторінки, HTTP-заголовки й robots забороняють індексацію. Після дозволу встановіть `BARBERLAB_ALLOW_INDEXING=true`, вкажіть реальний домен, перебудуйте сайт. Адмінпанель та API залишаються закритими для індексації.
6. Підтвердіть актуальність цін, команди, робочих днів, доступності входу/паркування, оплати карткою/NFC, кави, дитячих послуг і місця очікування. Дані — наданий знімок, а не жива перевірка Google.

## Чого бракує від власників

- Оригінальний векторний логотип для точного відтворення знака. Зараз використовується погоджена користувачем генерація підвищеної роздільності; це реконструкція, а не точна векторизація.
- Оригінальні фото салону та робіт. П’ять наданих портретів підключено; вихідні файли включено в assets/team. Галерея й окрема сторінка «Про нас» тимчасово прибрані; дані CMS збережені. Згенеровані інструменти та розмитий фон — декоративні матеріали, створені за запитом користувача.
- Підтверджений тижневий розклад, домен та конфігурація виробничого сервера. Для локального функціонування зовнішні ключі не потрібні.
- Перевірка відкриття Altegio з реального пристрою: всі CTA мають надане посилання; зовнішній веб-інструмент не відкрив сторінку; прямий HTTP-запит отримав 200, але завантажений динамічний інтерфейс і вільні слоти не перевірені. Сайт не створює фіктивних бронювань і не обіцяє попередній вибір послуги.

## Перевірки

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm run test:browser
node tests/run-isolated-admin.mjs
node tests/filter-regression.mjs
node tests/run-corrective-isolated.mjs
node tests/reference-browser.mjs
```

Браузерні тести потребують Microsoft Edge та запущеного сайту на `127.0.0.1:3000`. Вони використовують окремий headless-профіль без особистих cookies. Обгортка адміністративного тесту самостійно запускає окремий сервер на :3101 із тимчасовою базою та прибирає їх після перевірки. Не запускайте admin-browser.mjs напряму проти бази власника.

Результати та знімки — у `verification/`; докладніше у `VERIFICATION.md`. Production-залежності перевірено npm audit. Dev-інструментарій ESLint має upstream-застереження для braces/micromatch; на серверний runtime ці пакети не входять. Перед публічним запуском повторіть аудит і перевірки на вибраному хості.

## Джерела та ліцензії

- Логотип і бізнес-дані — надані користувачем; права на публічне використання підтверджує власник.
- На головній вступ і команда розташовані перед послугами. Закріплений хедер веде до секцій; повні списки послуг і майстрів залишаються окремими сторінками. Three.js не використовується. Фільтровані послуги доступні одразу, а рух зупиняється за налаштуванням reduced-motion.
- 15 PNG інструментів і розмитий фон створені вбудованим image_gen за дозволом користувача. Портрети майстрів — справжні надані фото. Точні промпти: assets/tool-generation.md, assets/background-generation.md, assets/logo-generation.md.

- Manrope та Oswald — SIL Open Font License 1.1. Шрифти з Google Fonts збережено локально; тексти ліцензій у `public/fonts/`. Сайт не звертається до Google Fonts під час перегляду.
